========================================================================
                    PSI MyBatis Starter 技术亮点总结
========================================================================

一、核心架构设计

1. **自动配置机制**
   - 采用 Spring Boot AutoConfiguration 模式，实现零配置启动
   - 通过 @Conditional 注解实现按需加载，避免不必要的资源消耗
   - 配置类使用 @RequiredArgsConstructor 简化依赖注入，符合 Spring 最佳实践

2. **拦截器链设计**
   - 采用责任链模式组织多个 InnerInterceptor
   - 分页拦截器与租户拦截器顺序可控，确保执行顺序正确
   - 支持动态启用/禁用各个拦截器，灵活性高

3. **配置化驱动**
   - 所有功能支持配置文件开关控制
   - 白名单表名支持配置扩展
   - 参数化设计，无需修改代码即可调整行为

二、核心功能亮点

4. **智能字段自动填充**
   - 基于 MetaObjectHandler 实现自动填充
   - 支持字段存在性检查，避免不存在字段的异常
   - 自动填充字段：createBy, createTime, updateBy, updateTime, tenantId, delFlag, status, version
   - 支持用户上下文自动获取，无需手动传递

5. **租户隔离机制**
   - 自动在 SQL 中添加租户ID过滤条件
   - 支持白名单配置，允许共享数据表（如数据字典）
   - 智能判断 SQL 是否已包含租户条件，避免重复添加
   - 支持查询、更新操作的租户过滤

6. **分页增强**
   - 集成 MyBatis-Plus 分页插件
   - 支持分页合理化配置（页码越界自动处理）
   - 支持 COUNT 查询优化（join 优化）
   - 可配置最大单页限制，防止大数据量查询

7. **乐观锁支持**
   - BaseEntity 内置 version 字段
   - 使用 @Version 注解实现乐观锁
   - 自动填充初始值，无需手动设置

三、扩展性设计

8. **白名单机制**
   - 支持通过配置文件动态添加白名单表
   - 默认包含数据字典表（sys_dict_type, sys_dict_data）、系统配置表（sys_config）
   - 大小写不敏感匹配，提高可用性

9. **条件化配置**
   - 每个自动填充字段都可独立开关
   - 分页插件可独立启用/禁用
   - 租户拦截器可独立启用/禁用

四、代码质量保障

10. **空值安全处理**
    - UserContext 获取用户信息时进行多重空值检查
    - 字符串转换 Long 时使用安全转换方法
    - SQL 处理前检查空值，避免 NPE

11. **日志友好**
    - 类和方法都有清晰的 JavaDoc 注释
    - 关键逻辑有注释说明
    - 便于后续维护和问题排查

12. **依赖注入规范**
    - 使用构造器注入，避免字段注入
    - 使用 Lombok @RequiredArgsConstructor 简化代码
    - 符合 Spring 推荐的依赖注入方式

五、应用场景覆盖

13. **多租户场景**
    - 自动租户隔离，避免数据越权访问
    - 白名单支持共享数据，减少重复存储

14. **CRUD 标准化**
    - 统一的实体基类，规范字段命名
    - 自动填充减少样板代码
    - 乐观锁保证并发安全

15. **分页查询**
    - 简化分页代码，一行代码实现分页
    - 自动处理分页参数，无需手动拼接 SQL

六、技术选型优势

16. **MyBatis-Plus 集成**
    - 利用成熟框架，减少重复造轮子
    - 社区活跃，文档丰富
    - 提供大量开箱即用的功能

17. **Lombok 优化**
    - 减少样板代码，提高开发效率
    - 自动生成构造器、getter/setter
    - 代码更简洁，可读性更高

18. **TransmittableThreadLocal**
    - 用户上下文支持线程池传递
    - 解决 ThreadLocal 在异步场景下的问题
    - 适用于分布式追踪、日志链路等场景

========================================================================
                    面试常见问题与回答参考
========================================================================

Q1: 为什么要自定义 MyBatis Starter？
A: 为了实现团队统一的技术规范，减少重复配置，提高开发效率。通过 Starter 封装通用功能，使业务模块可以快速接入，专注于业务逻辑开发。

Q2: 租户拦截器的实现原理是什么？
A: 基于 MyBatis-Plus 的 InnerInterceptor 接口，在 SQL 执行前拦截，动态添加租户ID条件。通过解析 SQL 语句获取表名，与白名单比对后决定是否添加租户条件。

Q3: 如何处理多租户场景下的共享数据表？
A: 通过白名单机制实现。在配置文件中指定不需要租户隔离的表名，拦截器会跳过这些表的租户条件添加，实现多租户共享数据。

Q4: 自动填充如何获取当前用户信息？
A: 通过 UserContext 工具类，使用 TransmittableThreadLocal 存储用户信息。在请求入口（如过滤器）设置用户信息，然后在自动填充时获取。

Q5: 分页插件和租户拦截器的执行顺序有什么讲究？
A: 分页拦截器应优先于租户拦截器执行。因为分页需要先获取正确的总记录数，如果先添加租户条件，分页统计会更准确。

Q6: 如何保证自动填充的安全性？
A: 自动填充前会检查字段是否存在（hasGetter/hasSetter），避免不存在字段导致的异常。同时对用户信息进行多重空值检查，确保不会因为用户信息缺失而导致错误。

========================================================================
                    配置示例
========================================================================

# application.yml 配置示例
psi:
mybatis:
    # 分页配置
    pagination-enabled: true
    max-limit: 500
    
    # 自动填充配置
    auto-fill-enabled: true
    fill-create-by: true
    fill-create-time: true
    fill-update-by: true
    fill-update-time: true
    fill-tenant-id: true
    fill-del-flag: true
    fill-status: true
    
    # 租户拦截器配置
    tenant-interceptor-enabled: true
    tenant-whitelist-tables:
    - sys_dict_type
    - sys_dict_data
    - sys_config
